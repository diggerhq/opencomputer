title: "Sessions"
description: "A suspended session has no runner but still answers reads and records writes; `sessions.resume` or sending a turn starts it again"
---

A session id is `cs_` followed by 16 characters. Fields of the `Session` object: [API schema](/reference/api-schema#objects).

## Status

| `status` | Meaning |
| --- | --- |
| `starting` | The runtime is starting. `runtime.starting` events give the phase: `computer`, then `agent` |
| `running` | A turn is running |
| `waiting` | An ask is open |
| `idle` | No turn is running |
| `suspended` | No runner holds the session. The host answers reads and records writes |

Each change is a `session.status_changed` event with `from` and `to`.

## Create and list

HTTP only: `POST /sessions` with a `CreateSessionBody`, and `GET /sessions`.

```json
{"input":"Run the test suite and fix what fails","title":"Fix tests","mode":"acceptEdits","metadata":{"ticket":"ENG-123"}}
```

Every field is optional ([API schema](/reference/api-schema#operations)). `id` is a session id chosen by the client; `input` is the first message. Accepted values for `model`, `effort`, `speed` and `mode` are in the session's `capabilities`.

`access` sets who may use the session ([Access](#access)). Without it, the session gets the organization's `apiAccessDefault`.

`GET /sessions` lists only the sessions you may use. That holds for admins too: an admin changes the access of a session they cannot use by its id ([Access](#access)).

## Read

`sessions.get` (`GET /sessions/{id}`) returns the `Session`, including the active turn id, queued turns, open asks, running subagents and `lastSeq`. `minSeq` waits for the journal: [Session journal](/api/overview#session-journal).

## Attach

`sessions.attach` (WebSocket only) subscribes the connection to the session's events. It returns the session and its `capabilities`: models with their effort levels, permission modes, and features.

```json
{"jsonrpc":"2.0","id":1,"method":"sessions.attach","params":{"sessionId":"cs_0123456789abcdef","tailTurns":3,"deltas":true}}
```

| Param | Meaning |
| --- | --- |
| `after` | Replay events with `seq` greater than this, then follow live |
| `tailTurns` | Replay the last 1 to 50 turns instead. `earlierTurns` in the result holds the turns before them |
| Neither | Live events only |
| `deltas` | Also send `delta` notifications (text as it is written) |
| `resume` | Start the runtime if the session is suspended |
| `readOnly` | Refuse writes to this session on this connection (`forbidden`, `reason: "read_only"`) |

| Related | Use |
| --- | --- |
| `/connect?attach=<sessionId>&tailTurns=3&deltas=1` | Attaches in the connection URL. The server answers with a `sessions.attached` notification carrying the same fields, or an `error` |
| `sessions.detach` | Ends the subscription |

| Error | Cause |
| --- | --- |
| `too_many_attached` | The connection already holds 20 attached sessions |
| `too_far_behind` | See [Events](/api/events) |

## Update

`sessions.update` (`PATCH /sessions/{id}`) changes any of `title`, `model`, `effort`, `speed`, `mode`, `archived` and `metadata`. It returns the session and a `seq`. Over HTTP it also takes `access` ([Access](#access)).

```json
{"jsonrpc":"2.0","id":2,"method":"sessions.update","params":{"sessionId":"cs_0123456789abcdef","mode":"plan","metadata":{"ticket":"ENG-124"}}}
```

| Item | Rule |
| --- | --- |
| `metadata` | Keys (up to 40 characters) are merged one by one. Values are strings of up to 500 characters, or null |
| `session.updated` event | `changes` maps each changed field to `{from, to}`. A metadata key is `metadata.<key>` |
| Model the harness does not accept | `invalid_request` with `field: "model"`. The session stays on its model |

## Access

Sessions started from the dashboard, opc or the API have an `access` field, `{"mode", "people"}`:

| `mode` | Who may use the session |
| --- | --- |
| `owner` | Only its owner |
| `org` | Every member of the organization |
| `people` | Its owner and the members in `people` (`usr_` ids). The owner is never listed |

Using a session means everything that reads or drives it: get, list, attach, history (events, turns, asks, subagents), writes, terminals and workspace files. Anyone with access drives the session with its owner's secrets and subscription. To someone without access, the session does not exist: `404 session_not_found`.

Set it when you create the session, or change it with `PATCH /sessions/{id}`:

```json
{"access":{"mode":"people","people":["usr_01j...","sam@example.com"]}}
```

| Item | Rule |
| --- | --- |
| Who may change it | The owner, anyone in `people`, or an organization admin. `canManageAccess` on the session says whether you may |
| A member of an `org` session who is not an admin | `403 forbidden` with `reason: "not_member"` |
| Admins | An admin may change the access of any session but may use only the ones its access lets them into. To get into an `owner` session, an admin adds themselves to `people`. While changing the access of a session they cannot use, an admin may send only `access`, and the response is `{"session":null,"access",...,"canManageAccess":true,"seq"}`. `GET /sessions/{id}` returns the same, so the admin can read the current access first |
| `people` | Up to 50 entries: `usr_` member ids, WorkOS `user_` ids or emails. Each must be someone in the organization who has used OpenComputer here. Otherwise the response is `400 invalid_request` with `field: "access.people"` and `reason: "unknown_member"` |
| Slack sessions | `access` shows `owner` and cannot be changed over the API: `403 forbidden` with `reason: "access_in_slack"`. Manage who drives a Slack session in its thread |
| Sessions from before access modes | `org` until someone changes them |
| Terminals | Owner, the members in `people`, or an admin in an `org` session ([Terminals](/api/terminals)) |
| After a change | Attached connections and open terminals that lose access are closed. HTTP reads may keep working for up to 30 seconds |

Access is HTTP only. `sessions.update` over the WebSocket does not take it.

### Organization default

`GET /settings` returns `{"settings":{"apiAccessDefault":"owner"}}`. `apiAccessDefault` is the access of new sessions started from the dashboard, opc or the API without `access`: `owner` (the default) or `org`. An organization admin changes it with `PATCH /settings` and `{"apiAccessDefault":"org"}`. Anyone else gets `403 admin_required`. Slack sessions keep their own default, set in Slack.

## Set aside

Triage lists the asks waiting on you. Setting a session aside moves its ask out of that list until something newer needs you. HTTP only: `PUT /sessions/{id}/aside` sets it, `DELETE /sessions/{id}/aside` brings it back. Both return the session.

```json
{"ref":"toolu_01AbCdEf"}
```

| Item | Rule |
| --- | --- |
| `ref` | The id of the ask being set aside: the session's oldest open ask |
| `aside` | True while `ref` is still the session's oldest open ask. Once that ask closes, `aside` is false again, with no `DELETE` |
| Caller | The session's owner, with `sessions:write`. Anyone else: `403 forbidden` with `reason: "aside_owner_only"` |
| Events | None. Setting a session aside does not change `lastActiveAt` |

## Compact

`sessions.compact` (`POST /sessions/{id}/compact`) queues a compaction as a turn and returns the same result as `turns.send`.

`instructions` (up to 10,000 characters) is passed to the harness's `/compact` command. The `session.compacted` event gives `beforeTokens`, `afterTokens` and `auto` (true when the harness compacted on its own). See Context and compaction.

## Suspend

`sessions.suspend` (`POST /sessions/{id}/suspend`) stops the session's runner. The journal and workspace stay on the computer.

| State when called | Result |
| --- | --- |
| Idle | Suspends |
| A turn is waiting on an ask | The turn is interrupted, then the session suspends |
| A turn is running and no ask is open | `409 session_busy`. Interrupt first |
| `ifIdle: true` and the session is not idle, or has running subagents or queued turns | The session, unchanged |
| Already suspended | The session, unchanged |

Suspending cancels queued turns, stops running subagents, closes open asks as `interrupted`, and records `runtime.suspended` with `reason: "requested"`. The other reasons are `idle` and `lost`.

## Resume

`sessions.resume` (`POST /sessions/{id}/resume`) starts the runtime of a suspended session and returns at once; `runtime.starting` and `runtime.connected` events follow. On a session that is not suspended it returns the session unchanged. [Sending a turn](/api/turns#send) to a suspended session also starts it.
