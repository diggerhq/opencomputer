## Owner

The person whose message started the session owns it. A session started by `start_thread` has its parent's owner and the same access.

In a team install the session:

- runs in the owner's workspace;
- gets the owner's secrets and variables, plus the session's own and the workspace-wide ones (see [Secrets and variables](/slack/secrets-and-variables));
- reads and posts to other threads with the owner's Slack access (see [Linked and spawned threads](/slack/linked-and-spawned-threads)).

## Who can steer

A new session starts open: everyone in its thread can drive it. An organization admin changes that default with `!access default owner`. The owner or an admin changes who drives one session with `!access` (see [Slack commands](/reference/slack-commands#access)).

| Person | Message that mentions `@computer` | Reply without a mention | Buttons on approvals, questions, plans |
| --- | --- | --- | --- |
| Can drive | Delivered | Delivered | Accepted |
| Cannot drive | Not delivered; the owner is asked once, with Allow and Not now buttons, and the message runs if they allow it | Kept, and given to the session as context with the next delivered message | Refused; ephemeral "This is waiting on someone else." |
| Not a full member of the workspace | Not delivered; ephemeral "Only full members of this workspace can drive sessions." | Not delivered | Refused with the same reply |

Anyone who can drive sends instructions, runs `!` commands (including `!stop` and `!mode`) and answers prompts. They act with the owner's workspace and secrets.

One-machine mode has no access control: every reply in a session thread is delivered.

<Note>Each session runs in its own container on a computer with `SP_LAUNCH=podman`, the default for a new one. On a computer still on `SP_LAUNCH=systemd`, every session runs as one Unix user and can read other sessions' files and secrets. See [What a session can reach](/slack/permission-modes#what-a-session-can-reach).</Note>

## When the bot stays silent

The model decides whether each delivered reply is for it. If not, nothing is posted: no message, no card, no footer.

- The model can misjudge either way.
- A silent turn still runs the model and counts towards usage.
- In a direct message, every message counts as addressed to `@computer`.
