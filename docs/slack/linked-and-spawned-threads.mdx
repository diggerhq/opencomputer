## Pasted links

When a message to the session contains a Slack message permalink, the gateway attaches the linked thread: its first message, the linked reply and the latest replies. The model receives it marked as data from Slack, not as instructions.

- At most 3 links per message are read; size limits are in Limits and defaults.
- The link must be in the same Slack workspace, and `@computer` must be a member of the conversation it points to.
- If reading takes more than 10 seconds, the message is delivered with a note that reading took too long.
- Messages forwarded into the message (up to 3) are attached with no access check.

### Access check

A linked thread is attached only if all of these can see the linked conversation:

1. The person who posted the link.
2. The session's owner.
3. Everyone in the session's conversation, when it is not the linked one.

| Linked conversation | Who counts as able to see it |
| --- | --- |
| Public channel | Every full member of the Slack workspace; a guest only if a member of the channel |
| Private channel or DM | Its members. Refused when the session's conversation is a public channel. |

The check also refuses when the session's conversation is shared with another organization, or when a member list it has to read has more than 5,000 members. On a refusal the model gets a note with the reason in place of the content.

## Reading and posting tools

Not in one-machine mode. Parameters: Agent tools.

| Tool | What it does | Limits |
| --- | --- | --- |
| `read_thread` | Reads another session by its id (`cs_…`), its link from the web app, or the link of the Slack thread it runs on: what was sent to it and what its agent said, over its last 20 turns. | Only this session, sessions it started, and its track's agent and threads. 60,000 characters. Never asks for approval. |
| `post_thread` | Posts a reply into another Slack thread for the owner. | Only from a session started in Slack, into a thread whose session `read_thread` could read. 4,000 characters. Asks for approval unless the mode is `bypassPermissions`. |

`post_thread`:

- replies in the thread, never at the channel's top level;
- neutralizes `@channel`, `@here`, `@everyone` and user-group mentions;
- reaches the session in that thread as a message from its owner, after a line saying it was posted for them by the session in another thread.

## Spawned threads

`start_thread` starts a new session that runs in parallel. Not in one-machine mode. Parameters: Agent tools.

| Stage | Who | What happens |
| --- | --- | --- |
| Brief | Agent | Optional. Writes a Markdown file in a workspace repository, commits it and pushes it to that repository's default branch. The tool refuses a brief that is not there. |
| Call | Agent | Calls `start_thread` with a one-line `task`, optionally the `brief` path, and `track: true` to start it in this session's track. Outside `bypassPermissions` the call asks for approval. |
| Post | Backend | When the parent has a Slack thread, posts the new session's first message at the top level of the parent's channel: the task and, with a brief, its path and link. |
| Start | New session | Runs in that thread. With a brief, it is told to read the brief first and report there. |

| The new session's | Value |
| --- | --- |
| Owner, who may use it | The parent's |
| Track | The parent's with `track: true`, else none |
| Conversation | Its own |
| Session directory | Its own, starting from each repository's default branch |
| Context | The task and the pushed brief only |

- 8 starts per runner, and at most 10 open threads started by one session.
- `start_thread` returns the new session's id. The parent is not told when the child finishes; it can read the child with `read_thread`.
- Steer or stop the child in its own thread. Stopping the parent does not stop it.
