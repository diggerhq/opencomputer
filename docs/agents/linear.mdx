---
title: "Linear agents"
description: "Make a deployed agent a teammate people delegate issues to and mention in Linear"
---

Connect an agent to Linear and people can delegate issues to it and mention it,
under the name you give it. Its tool calls and replies appear in the issue's
thread. You write no webhook or Linear client code.

```tsx
import { useInput } from "@opencomputer/agent";

export default function Agent() {
  const input = useInput();
  return `You are a teammate in Linear. Work on this and reply in the thread:\n\n${input.text ?? ""}`;
}
```

## Connect

1. In the project's **Connections** tab, choose **Create Linear agent** on the
   environment's row and name it. Names can't contain "Linear".
2. Choose **Open Linear to create the app**. The page is prefilled; create the app.
3. Paste the app's client ID, client secret and webhook signing secret.
4. Choose **Authorize in Linear**. A workspace admin must approve.
5. Delegate an issue to the agent. The panel shows **First session received**.

Each environment needs its own Linear app. Tokens never reach the agent, its
logs or the browser.

## Talking to it

- **Delegate an issue** or **mention it** in a comment to start a session.
- **Reply in the session's thread** to continue, even after it finished.

A top-level comment without a mention is not delivered. Anyone on the team can
reply; the agent answers the thread, not a person.

## What it receives

Each message is a [channel input](/agents/inputs) with
`channel.provider: "linear"`. `text` is the message, or Linear's prompt
context for the first one. `payload` is a `LinearInputPayload`:

| Field | Meaning |
| --- | --- |
| `issue` | `{ id, identifier, title, description, url, team }` |
| `origin` | `{ parent?, createdByAgent }`, read when the session starts and fixed for its life |
| `action` | `created` for the first message, `prompted` after |
| `session`, `comment`, `previousComments`, `guidance` | The thread and your workspace's agent guidance, as Linear sent them |

## What it writes

| The agent | Linear shows |
| --- | --- |
| Calls a tool | An action with a one-line summary (never raw arguments) |
| Finishes its turn | The final message as a response |
| Calls `ask` | A question awaiting input, options as buttons |
| Fails or is stopped | An error |

A GitHub pull request URL in the final message becomes the session's link.

## Ask before acting

```tsx
export default function Agent() {
  const input = useInput();
  if (!input.answer) {
    useTool("ask");
    return `Propose a plan, then ask whether to go:\n\n${input.text ?? ""}`;
  }
  useTool(createSubIssues);
  return `You were told "${input.answer.text}". If that means go, do it.`;
}
```

The reply arrives with `input.answer`. Messages written in the meantime arrive
with it in `input.steering`. Linear holds messages typed while the agent works
until it finishes, so tell people to send them before answering.

## Stop

Linear's stop button interrupts the turn, discards queued messages and closes
any open question. A later reply continues the same session.

## Call Linear

For documents, sub-issues or status changes, declare `useService("linear")`
and call Linear's GraphQL API. The call acts as the agent's own Linear app.

```tsx
const response = await callService({
  service: "linear",
  method: "POST",
  path: "/graphql",
  body: JSON.stringify({ query, variables }),
});
```

Only `POST /graphql` is allowed. Issues the agent delegates to itself start new
sessions with `origin.createdByAgent: true`. For code, connect the project's
[GitHub App](/agents/github).

## Disconnect

Choose **Disconnect** in the Linear panel. The app stays in your Linear
workspace; delete it there if you no longer need it.

## Limits

- One connection per agent per environment, and one per Linear app.
- No concurrency limit: every delegated issue runs its own session.
- `ask` isn't available on the `microvm` runtime.
- Stopping a session doesn't stop issues it delegated.
