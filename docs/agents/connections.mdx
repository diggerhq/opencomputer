---
title: "Connections and MCP"
description: "Attach user-scoped services and managed MCP servers from agent code"
---

Connections authorize external services without placing provider credentials
in source, prompts, or the agent runtime. Agent code declares what it needs;
each OpenComputer user authorizes their own account.

## Request a connection from code

```tsx
import { connection, useConnection } from "@opencomputer/agent";

const github = connection("github");

export default function Agent() {
  useConnection(github);
  return "Help the user inspect and work with their GitHub account.";
}
```

Connection declarations are safe to commit. They contain identifiers, not
OAuth access tokens.

## Authorize an account

```bash
npx opencomputer connection add github --alias work
npx opencomputer connection add gmail --alias personal
npx opencomputer connection add calendar --alias work-calendar
npx opencomputer connection list
```

Remove an authorization by alias or connection ID:

```bash
npx opencomputer connection remove work
```

Connections are scoped to the authenticated user. Deploying an agent does not
grant every user access to the developer's connected accounts.

## Attach an MCP server

```tsx
import {
  connection,
  defineMcpServer,
  useInput,
  useMcpServer,
} from "@opencomputer/agent";

const github = connection("github");
const docs = defineMcpServer({
  id: "company-docs",
  url: "https://mcp.example.com/server",
  connection: github,
});

export default function Agent() {
  const input = useInput();
  if (input.text?.includes("documentation")) useMcpServer(docs);
  return "Use company documentation when it is relevant to the request.";
}
```

Managed MCP URLs must use HTTPS. Because `useMcpServer` can be conditional,
the server does not need to be exposed to every render of the agent.

## Missing authorizations

The managed runtime can list connection metadata available to the current
session and request an authorization when a declared service is missing. The
user completes that flow in OpenComputer; credentials are not returned to the
model or application.
