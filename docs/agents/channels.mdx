---
title: "Channels"
description: "Connect a deployed agent alias to Slack"
---

A channel delivers external messages to the same durable session runtime used
by React, the API, CLI, and playground. Agent behavior remains defined in code.

## Connect Slack

<Steps>
  <Step title="Deploy an agent">
    Run `npm run deploy -- --alias production`. Slack connects to an alias so
    later versions can be promoted without reinstalling the app.
  </Step>
  <Step title="Open Channels">
    Open the project in the OpenComputer dashboard, choose the agent and
    environment, then select **Channels**.
  </Step>
  <Step title="Create the Slack app">
    Start **Connect Slack**, copy the generated manifest, and create the app in
    Slack using that manifest.
  </Step>
  <Step title="Complete installation">
    Enter the requested Slack application values and install the app. Secrets
    are stored by OpenComputer rather than committed to the project.
  </Step>
</Steps>

Direct messages and supported Slack threads create or resume isolated agent
sessions. Channel sessions appear in the project's **Sessions** view.

## React to channel input

Use the same agent function for every input source:

```tsx
import { useInput } from "@opencomputer/agent";

export default function Agent() {
  const input = useInput();
  return input.source === "channel"
    ? "Reply briefly and avoid exposing private context in a shared channel."
    : "Give a complete and helpful response.";
}
```

## User identity and connections

A Slack user links their own OpenComputer identity before the agent can use
that person's service connections. A shared channel does not inherit the Slack
installer's Gmail, GitHub, Calendar, or other authorizations.

Disconnecting Slack stops new channel messages without deleting the agent,
deployment history, or previous sessions.
