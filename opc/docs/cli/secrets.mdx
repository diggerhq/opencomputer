---
title: "Secrets"
description: "Set, list and delete a session's own secrets from the command line."
---

```bash
opc secrets set AWS_SECRET_ACCESS_KEY -s 7f3a      # prompts; nothing is shown as you type
printf %s "$AWS_SECRET_ACCESS_KEY" | opc secrets set AWS_SECRET_ACCESS_KEY -s 7f3a
opc secrets ls -s 7f3a
opc secrets rm AWS_SECRET_ACCESS_KEY -s 7f3a
```

`opc secrets` manages one session's own secrets, the layer the dashboard calls "This session only". The session's next command has each one as an environment variable, or, with `--file`, `$NAME` holds the path of a file with the value. A session secret wins over a personal or organization one of the same name.

- **The value never goes on the command line.** `set` reads it from standard input when that is not a terminal, else from a prompt that does not echo. A trailing newline is dropped, so `echo "$X" |` works; with `--file` the input is kept exactly. An empty value is refused.
- **Secret values never come back.** `ls` prints names, who set them and when; nothing prints a secret's value, and errors never include one. A variable's value is shown to the session's owner.
- **Which session.** `set` and `rm` need `-s <id>` (`-s -` is the last session on this machine). `ls` takes the id in place or with `-s`, and otherwise uses the last session when standard input is a terminal.
- **Who can.** Anyone who can see the session: its owner, or a member it is [shared](/cli/sharing) with, for a session started from the dashboard, `opc` or the API; only its owner for one started in Slack. Others get `no session … that you can see`. Anyone who can see it can list its secrets; only the session's owner can set, replace or delete them, and anyone else, organization admins included, is refused with exit code 3. Setting and deleting need an API key with the `secrets:write` scope: `opc login` gets one, a key with every scope (`*` or `sandbox:*`) does not. A session's own key cannot use these commands.
- **Limits.** Names are letters, digits and `_`, not starting with a digit, at most 64; names that would change how a session runs (`PATH`, `LD_*`, `GIT_*`, …) are refused. A value is at most 64 KB. A session holds at most 64 secrets, and a person makes at most 30 changes a minute. A session's secrets are deleted once it has gone 30 days without running a command.

`--json` on `ls` prints `{ "secrets": [Secret…] }` (see [Secrets](/api/http/secrets#a-sessions-own-secrets)).
