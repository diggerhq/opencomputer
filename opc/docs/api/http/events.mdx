---
title: "Events"
description: "Read a session's event log over HTTP, page by page with a cursor."
---

```http
GET /sessions/{id}/events
```

```bash
curl -s "$API/sessions/cs_7f3a9k2m4q8r1t6v/events" -H "x-api-key: $OPENCOMPUTER_API_KEY"
```

| Query | Meaning |
| --- | --- |
| `after` | The `cursor` of the previous page: return the events after it. Omit to start at the beginning. |
| `limit` | 1 to 500. Default 100. |
| `tailTurns` | Instead of `after`, 1 to 50: the full events of the last this many turns, with the turns before them summarized in `earlierTurns`. See [Start from the end](#start-from-the-end). |
| `turnId` | Only events of this turn |
| `types` | Only these types, separated by commas. A trailing `*` matches a prefix, such as `tool.*`. An unknown type matches nothing. |

```json
{
  "events": [
    { "id": "ev_…", "seq": 1, "type": "session.created", "…": "…" },
    { "id": "ev_…", "seq": 2, "type": "message.received", "…": "…" }
  ],
  "cursor": "…",
  "lastSeq": 1184,
  "hasMore": true
}
```

`events` are in ascending `seq`. `cursor` is where the page ends: send it back as `after` for the next one. It is opaque: store it and compare it for equality, never read or build one. A bare `seq` as `after` gets `409 reset`. `lastSeq` is the session's newest `seq` when the page was read. `hasMore` is `true` when events past this page remain. Deltas are never included. See [Events](/api/reference/events) for every type.

Events read here are complete, including a tool's large `input` or `output`.

With `turnId` or `types`, `seq` values have gaps. Keep sending the page's `cursor` as `after`.

## Read a whole log

Start without `after`, and repeat with the page's `cursor` until `hasMore` is `false`.

```bash
q="limit=500"
while :; do
  page=$(curl -s "$API/sessions/$id/events?$q" -H "x-api-key: $OPENCOMPUTER_API_KEY")
  jq -c '.events[]' <<<"$page"
  jq -e '.hasMore' <<<"$page" >/dev/null || break
  q="limit=500&after=$(jq -r '.cursor | @uri' <<<"$page")"
done
```

`opc log --json` prints the same.

## Start from the end

A long session can have tens of thousands of events. To show it, a client needs its last turns in full and a line for each earlier one, not the whole log. `tailTurns=n` returns that in one request:

```json
{
  "events": [{ "id": "ev_…", "seq": 1102, "type": "message.received", "…": "…" }],
  "earlierTurns": [{ "id": "tn_1b4m8q9x2c7v", "status": "completed", "input": "…", "…": "Turn" }],
  "cursor": "…",
  "lastSeq": 1184,
  "hasMore": false
}
```

`events` are every event of the last `n` turns and after them. `earlierTurns` are the [Turns](/api/reference/objects#turn) before those, newest first, at most 50. Read further back with `turnId`, or from the start without `tailTurns`. `tailTurns` cannot be combined with `after`.

## Follow a session

Call this route with `after` set to the last `cursor` you have, every few seconds. Each request answers at once, with `events: []` and the same `cursor` when nothing is new. This is enough for a script. The loop also follows a [reset](#reset)'s `cursor`, and starts over when it is `null`.

```bash
q=""
while :; do
  page=$(curl -s "$API/sessions/$id/events?$q" -H "x-api-key: $OPENCOMPUTER_API_KEY")
  jq -c '.events[]?' <<<"$page"
  c=$(jq -r '(.cursor // .error.cursor // empty) | @uri' <<<"$page")
  q=${c:+after=$c}
  sleep 5
done
```

For anything a person watches, use [Live](https://docs.opencomputer.dev/api/live) instead: events arrive the moment they are recorded, and text streams as it is written. Live holds no history: read here up to the end, then subscribe with the last `cursor`, and read here again whenever a pushed range does not start at your cursor.

## Reset

`409 reset` means the cursor's position no longer exists: it is not a cursor of this session's events, it is past the log's end, or the session's computer was lost mid-turn and the log was rewritten from a point. The error carries `cursor` and may carry `seq`. Discard what you applied above `seq`, then read on with `cursor` as `after`. With `cursor: null`, start again without `after`. See [If a computer is lost](/api/model#if-a-computer-is-lost).

| Status | Code | When |
| --- | --- | --- |
| `400` | `invalid_request` | `limit` is out of range, or `tailTurns` is sent with `after` |
| `404` | `session_not_found` | |
| `409` | `reset` | See [Reset](#reset). `error.cursor` is where to read on, or `null`; `error.seq`, when present, is the last event to keep. |
