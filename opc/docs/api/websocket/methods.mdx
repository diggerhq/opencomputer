title: "Methods"

A method is named `<plural resource>.<verb>`, and maps to the HTTP route of the same resource and verb. Its params are that route's path parameters, query and body, flattened into one object, and its result is the route's response. Every session method takes `sessionId`, except the terminal methods after `terminals.open`.

The WebSocket carries no session write. Sending a turn, answering or dismissing an ask, interrupting, cancelling a turn, stopping a subagent, compacting, suspending, resuming and changing a session's settings are HTTP only, because every write goes through the session's inbox, which checks who may write to it. `opc` sends them over HTTP too.

| Method | HTTP equivalent |
| --- | --- |
| `sessions.get` | [`GET /sessions/{id}`](/api/http/sessions#get-a-session) |
| `turns.get` | [`GET /sessions/{id}/turns/{turnId}`](/api/http/turns#get-a-turn), with `turnId` |
| `asks.list`, `asks.get` | [`GET /sessions/{id}/asks`](/api/http/asks#list-asks) and [`GET /sessions/{id}/asks/{askId}`](/api/http/asks#get-an-ask), with `askId` |
| `subagents.list`, `subagents.get` | [`GET /sessions/{id}/subagents`](/api/http/subagents#list-subagents) and [`GET /sessions/{id}/subagents/{subagentId}`](/api/http/subagents#get-a-subagent), with `subagentId` |
| `events.list` | [`GET /sessions/{id}/events`](/api/http/events), except that `after` here is a `seq` and the result has no `cursor` |
| [`terminals.open`, `terminals.resize`, `terminals.eof`, `terminals.close`](/api/websocket/terminals) | none |
| `ping` | none |

Everything not in this table is HTTP only, such as every session write, creating and listing sessions, files and tickets. The WebSocket carries no session events: watch sessions on [Live](https://docs.opencomputer.dev/api/live).

## Telemetry

`telemetry` is a notification a client may send, with no `id` and no response: `{ v: 1, client: { name, version, os, arch }, events: [{ name, at, sessionId?, turnId?, data }] }`, 1 to 20 events, at most 16 KiB, at most 6 a minute. The server keeps only the event names and keys it knows (`opc`'s are listed in [Telemetry](/reference/telemetry)) and drops anything else without closing the connection.

## Notifications

| Method | Params | Sent |
| --- | --- | --- |
| `ready` | `connectionId`, `server`, `protocol`, `limits`, `expiresAt`, `expiresInMs` | Once, first. See [Connecting](/api/websocket/connect#open). |
| `terminal.exited` | `terminalId`, `exitCode`, `signal` | When a [terminal](/api/websocket/terminals#terminalexited) ends |

## Errors

Errors follow JSON-RPC 2.0:

```json
{
  "jsonrpc": "2.0", "id": 7,
  "error": { "code": -32000, "message": "Ask already answered", "data": { "code": "ask_closed", "status": 409, "message": "This ask was already answered.", "requestId": "req_8k2m4q7x1v9c", "retryable": false, "ask": { "…": "…" } } }
}
```

| `code` | Means |
| --- | --- |
| `-32700` | The frame is not JSON |
| `-32600` | Not a valid JSON-RPC request |
| `-32601` | Unknown method |
| `-32602` | Invalid params. `data` is always `{ "code": "invalid_request", "status": 400, "field": "…" }`, with `field` the dotted path of the param. Unknown params are invalid too. |
| `-32000` | Any API error. `data` is exactly what the HTTP route would return as `error`, with `status` added. |

Branch on `data.code`, which is the same over HTTP and WebSocket. See [Errors](/api/reference/errors).
